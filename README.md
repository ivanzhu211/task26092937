# reconcile — 采购对账匹配库

将供应商账单行分配到实际收货批次，输出可追溯的对账建议。
只处理同一供应商、同一币种的已审核单据快照；金额用整数美分，数量用整数件，不计税费。

## 接口

- `BuildLedger(receipts []Receipt, returns []Return) Ledger`
  生成保留批次身份和实际单价的净收货账本。退货按批次 ID 扣减原批次，不跨批次扣减。
- `Reconcile(ledger Ledger, bills []BillLine) Reconciliation`
  返回账单行到收货批次的数量分配（`Allocations`）、总匹配数量（`TotalMatchedQty`）
  与总绝对价差（`TotalAbsPriceDiff`，单位：美分）。不修改输入账本，可重复调用。

## 算法

建模为最小费用最大流：源点 → 账单行（容量 = 账单数量，费用 0），
账单行 → 批次（仅当 SKU 相同且采购单行 ID 在允许集合内，费用 = |账单单价 − 批次单价|），
批次 → 汇点（容量 = 批次净收货量，费用 0）。
所有费用非负，逐条最短路增广（SSP + 势函数 Dijkstra）即得：
先最大化总匹配数量，再在所有达到该数量的方案中最小化总绝对价差。
两个目标值与输入顺序无关。

## 运行

```sh
go build ./...   # 编译
go test ./...    # 运行全部测试
```

测试覆盖：退货扣减原批次、账单争用批次的重新分配、同匹配量下最小绝对价差（含拆分分配）、
空允许集合、SKU/采购单行过滤、账本不被消耗、输入顺序无关性、正负价差不抵消。
